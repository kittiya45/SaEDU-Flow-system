สถาปัตยกรรมภาพรวม

Vanilla JS SPA + Supabase + Vercel

ไม่มี framework ไม่มี JS bundler — โค้ดรันตรงในเบราว์เซอร์จาก static file ขั้นตอน build มีสองอย่าง: คอมไพล์ Tailwind CSS + สร้าง SQL bundle สำหรับคัดลอกใน Dev Panel

  • Frontend: ไฟล์ .js ที่ root — แชร์ global scope (ไม่มี ES modules) โหลดด้วย defer ตามลำดับใน index.html
  • Backend: Supabase (Postgres + Auth + Storage + Edge Functions) — เรียก PostgREST ด้วย fetch ผ่าน helper dg/dp/dpa/dd ใน config.js ไม่ใช้ query builder (ใช้ sb.auth.* และ RPC บางตัวเท่านั้น)
  • Hosting: Vercel — auto-deploy เมื่อ push main (vercel.json รัน npm run build)
  • เอกสารเชิงลึก: CLAUDE.md · manual.html · หน้านี้

เริ่มพัฒนาในเครื่อง

clone → build → serve
git clone https://github.com/kittiya45/SaEDU-Flow-system.git
cd SaEDU-Flow-system
npm install
npm run build        # CSS + สร้าง dev-sql-bundle.js
python3 -m http.server 8000
# เปิด http://localhost:8000
  • แก้ class Tailwind ใน .js → ใช้ npm run watch หรือรัน npm run build หลังแก้ SQL ใน supabase/
  • npm run build:css / npm run build:sql — แยกรันได้
  • styles.tailwind.css gitignore ไว้ — ต้อง build เองก่อนเสิร์ฟ
  • dev-sql-bundle.js ควร commit / regenerate ตอน deploy — ปุ่ม “คัดลอก SQL” อ่านจาก bundle นี้
i
ไม่มี lint/test — ตรวจงานด้วยการใช้จริง · ชี้ฐานข้อมูล production เสมอ — ระวังตอนทดสอบที่เขียนข้อมูล · ใช้แท็บ “ทดสอบระบบ” สำหรับ sandbox

กับดักที่พบบ่อย

อ่านก่อนไล่บั๊ก
  • แก้แล้วไม่เปลี่ยน → ลืมบัมป์ ?v=N หรือยังไม่ hard-refresh
  • Edge “Failed to fetch” → ห้ามส่ง H ตรง ๆ · หรือฟังก์ชันยังไม่ deploy
  • คัดลอก SQL Failed to fetch → ใช้ dev-sql-bundle.js (npm run build:sql)
  • showConfirm ล้าง modal → capture ค่าก่อน confirm
  • ห้ามต่อ string เป็น Tailwind class — ใช้ lookup table
  • raw fetch → ใช้ H.Authorization + เช็ค r.ok
  • dg() อาจคืน error object → เช็ค Array.isArray()
  • ลบผู้ใช้ → unlink FK ตาม _admDelConfirmed()
  • อนุมัติไม่ atomic → ซ่อมสถานะใน Dev Panel / workflow_action
  • free-text ต้อง esc() ก่อนใส่ HTML

สิทธิ์นักพัฒนา ระยะ 1–3

ดูแลระบบโดยแอดมินแตะน้อยที่สุด
ระยะสิ่งที่ได้SQL / Deploy
1 เช็กลิสต์ SQL · แผง integration · form_templates phase1_dev_extras.sql · integration-status
2 workflow UI · ซ่อมขั้นสูง · ลบเอกสาร · export config phase2_dev_ops.sql
3 จัดการผู้ใช้จำกัด · รีเซ็ตรหัส · overdue จาก UI phase3_dev_users.sql · admin-set-password

ทำได้ / ไม่ได้

  • ได้ config · ซ่อม/ลบเอกสาร · อ่าน logs · จัดการ users (ยกเว้น ROLE-SYS) · รีเซ็ตรหัส · มอบ ROLE-DEV
  • ไม่ได้ ลบผู้ใช้ · CSV · เพิ่มอาจารย์ · ตั้ง ROLE-SYS · admin-delete/create-user · ลบ history/notifications

มอบสิทธิ์

  1. รัน create_dev_role.sql (+ phase2/3 ถ้ายังไม่รวม)
  2. แอดมินอนุมัติ → ตั้ง ROLE-DEV (ครั้งแรก)
  3. นักพัฒนาคนอื่นมอบ ROLE-DEV ให้กันได้ที่แท็บจัดการผู้ใช้
